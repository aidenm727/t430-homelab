## Distinct Gap

### Candidate capability

**Human Engineering Control Surface**

### Working product name

**Aiden Platform Console**

Naming remains open. The durable opportunity title should describe the capability rather than permanently decide the product brand.

### Problem

GitHub and Atlas provide canonical and deterministic engineering state, but the owner lacks one human-facing place to understand:

- current mission and tasks
- lifecycle and checkpoint state
- pending approvals
- scope and authority
- linked issues, branches, and pull requests
- verification and evidence
- capabilities, systems, documentation, agents, and infrastructure relationships
- blockers and next valid actions

The repository and CLI remain necessary but are not sufficient as the full human operating interface.

### Candidate outcome

Provide a generated human view over repository, GitHub, and Atlas evidence without creating an independently mutable source of truth.

### Minimal first experience

- Home
- Task Detail
- Approval Queue
- Review and Evidence
- Platform Map

### Dependencies

Primary dependencies:

- `EO-2026-013`
- `EO-2026-014`
- `EO-2026-015`
- `EO-2026-016`
- `EO-2026-017`
- `EO-2026-021`

Supporting relationships:

- `EO-2026-007`
- `EO-2026-011`
- `EO-2026-019`
- `EO-2026-020`

### Non-goals

The candidate must not imply:

- a replacement operating-system kernel
- a second canonical database
- a general workflow engine in the first implementation
- provider ownership of platform state
- automatic merge or deployment
- autonomous architectural decisions
- immediate implementation
- modification of EO-2026-013
- authorization of Checkpoint B1b2 or B2
