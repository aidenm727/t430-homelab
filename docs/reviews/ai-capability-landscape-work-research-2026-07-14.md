# Aiden Platform Cloud-AI Capability Landscape and Operating Recommendation

**Research date:** July 14, 2026
**Decision horizon:** the next 8–12 weeks
**Owner baseline:** ChatGPT Plus; Aiden Platform Project; GPT-5.6 Sol with High reasoning; training disabled; Default project memory; Library enabled
**Currency:** USD, United States pricing, before tax, unless stated otherwise

## Research method and confidence

This is a decision report, not a universal model ranking. Changing product facts were checked against official product, pricing, help, privacy, and developer documentation on the research date. The supplied Aiden repository snapshots were treated as the primary source for platform architecture and current mission.

- **Confirmed fact** means supported by an official source or the supplied Aiden records.
- **Aiden inference** means a recommendation derived from those facts and the owner's stated operating principles.
- Published limits are included where providers document them. “Expanded,” “higher,” or dynamically allocated usage is not converted into an invented message count.
- A model available through an API or intermediary is not treated as equivalent to the model provider's native application.

## 1. Executive conclusion

### Decision

**Keep ChatGPT Plus as the incumbent. Do not add a standing subscription, API account, cloud AI platform, or local-AI workload yet. First evaluate the high-value capabilities already inside Plus: ChatGPT Work, Deep Research, and Codex. Then run a matched Claude comparison.**

The current hypothesis is supported, with two refinements:

1. “Evaluate Work” should mean a real deliverable workflow, not another chat. Work is a native mode included with Plus, not a separate business plan. OpenAI positions Chat for quick questions, Work for longer research and deliverables, and Codex for repository and software work. ([OpenAI: Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex))
2. “Evaluate Claude seriously” should begin with matched, read-only work on Claude Free. Pay for one month of Claude Pro only if Free results are competitive and Pro-only Claude Code or Cowork is the capability that must be tested. As of the research date, Claude Pro is $20 month-to-month and includes both products, but its newest Fable 5 model is available through separately billed usage credits rather than ordinary plan usage. ([Claude pricing](https://claude.com/pricing), [Anthropic: redeploying Fable 5](https://www.anthropic.com/news/redeploying-fable-5))

### Highest-value operating stack now

| Layer | Recommended Aiden component | Role |
|---|---|---|
| Canonical truth | GitHub repository | Architecture, decisions, implementation, and durable engineering knowledge |
| Deterministic interface | Atlas | Inspect live state, validate readiness, expose traceable engineering reasoning |
| Primary reasoning environment | Existing ChatGPT Project with GPT-5.6 Sol High | Architecture, synthesis, explanation, and planning already proven in real work |
| Research and deliverables | ChatGPT Work + Deep Research | Source-grounded research and finished Markdown/docs/spreadsheets/decks; included but not yet evaluated |
| Repository execution | Codex | Local repository inspection, bounded edits, commands, tests, and review; included but not yet evaluated |
| Independent comparison | Claude Free, followed conditionally by one month of Claude Pro | Test whether Claude's native behavior, Claude Code, or Cowork creates recurring differentiated value |
| Human authority | Owner | Select objectives, approve material changes, interpret evidence, and decide what becomes canonical |

**Aiden inference:** the largest near-term gap is not access to another frontier model. It is the lack of a repeatable evaluation loop that measures real-task quality, owner intervention, verified correctness, learning, authority discipline, and usage consumption across native environments.

### Hold decisions

- **No ChatGPT Pro:** the $100 and $200 tiers primarily add Pro reasoning and 5×/20× Plus usage. There is no demonstrated cap or Sol Pro requirement. ([OpenAI: Pro tiers](https://help.openai.com/en/articles/9793128-about-chatgpt-pro-tiers))
- **No standing Claude Pro yet:** it would initially overlap ChatGPT's chat, research, project, deliverable, and coding surfaces.
- **No Poe, Perplexity Pro, or similar subscription yet:** model breadth or search specialization has not been shown to beat included native capabilities on recurring Aiden work.
- **No API or router yet:** there is no bounded programmatic Aiden workflow with machine-readable inputs/outputs, an evaluation set, and a budget boundary.
- **No major-cloud AI platform:** Microsoft Foundry, AWS Bedrock, and Google's Gemini Enterprise Agent Platform solve application deployment, IAM, governance, and scale—not the owner's current individual knowledge-work problem.
- **No local AI now:** the current mission explicitly marks premature local AI and major hardware changes as non-priorities. The available host is useful future optionality, not present justification.

## 2. Landscape taxonomy

The useful unit of analysis is a capability and access model, not a brand.

| Category | What is actually purchased or operated | Representative products | Key distinction |
|---|---|---|---|
| 1. General-purpose consumer assistants | A seat in a conversational application with a provider's models and native features | ChatGPT Plus/Pro, Claude Free/Pro/Max, Google AI plans | Subscription access; not an API entitlement |
| 2. Project, memory, and knowledge workspaces | Persistent context, files, preferences, and project organization | ChatGPT Projects/Library, Claude Projects/Memory, Gemini ecosystem | Continuity and context management can matter more than model differences |
| 3. Native research and deliverable environments | Agentic research plus document, spreadsheet, presentation, or site creation | ChatGPT Work/Deep Research, Claude Cowork/Research, Perplexity Research/Create, Gemini Deep Research | Produces researched artifacts; more than a chat response |
| 4. Coding agents and engineering environments | Repository access, terminal/tool use, edits, tests, review, and sometimes cloud PR work | Codex, Claude Code, GitHub Copilot, Jules, Cursor, Google Antigravity | Execution surface and repository integration are first-class capabilities |
| 5. Source-grounded research and learning | Answers constrained to selected sources, with citations and learning formats | NotebookLM, ChatGPT Deep Research, Perplexity, Gemini Deep Research | Grounding and traceability, not merely a larger context window |
| 6. Multi-model consumer applications | One UI and point pool spanning models from several providers | Poe; Perplexity as a search-centered hybrid | Convenient model access, but usually omits provider-native projects, coding, and agent features |
| 7. Direct model APIs | Metered inference, tool calls, structured output, batch, embeddings, or realtime APIs | OpenAI API, Anthropic API, Gemini API | Programmable and usage-priced; subscriptions do not include it |
| 8. Unified API routers and marketplaces | One API, consolidated billing, routing, fallback, and model catalog | OpenRouter, Hugging Face Inference Providers, Perplexity Agent API | Adds an intermediary and provider-policy matrix |
| 9. Major cloud model and agent platforms | Models plus IAM, private networking, data services, runtime, evaluation, guardrails, observability, and deployment | Microsoft Foundry, AWS Bedrock, Gemini Enterprise Agent Platform | Enterprise application platform; not a personal AI subscription |
| 10. Specialized hosted open-model inference | Serverless or dedicated access to open-weight models and accelerators | Together AI, Cloudflare Workers AI, Fireworks, Groq, Replicate | Useful for throughput, price, model control, or open-model deployment |
| 11. Local and self-hosted AI | Model weights, local runtime, hardware, storage, updates, and operations | LM Studio, Ollama, llama.cpp, vLLM, Open WebUI | Maximum deployment control; also maximum operational responsibility |
| 12. Agent integration and authority layer | Connectors, MCP, plugins, skills, schedules, browser/computer use, approvals, identity | Cross-provider ecosystems | Determines what an agent can know and do; often higher risk and value than model access |
| 13. Evaluation, observability, and governance | Task sets, traces, cost/latency data, approval logs, guardrails, and policy | Native cloud tools and independent frameworks | The missing control plane for reliable multi-agent or production use |

### 3.6 Local and self-hosted AI

Local AI is a deployment category, not a single product and not automatically a cost-saving choice.

- **LM Studio** can run downloaded models, document RAG, and a local OpenAI-compatible server entirely offline; it states that local chat and documents remain on-device. ([offline operation](https://lmstudio.ai/docs/app/offline))
- **Ollama** packages local model execution and an API on macOS, Windows, and Linux, while also offering cloud models; the distinction must be explicit. ([Ollama quickstart](https://docs.ollama.com/quickstart))
- **llama.cpp** emphasizes broad hardware support, quantization, CPU/GPU hybrid inference, and an OpenAI-compatible local server. ([llama.cpp](https://github.com/ggml-org/llama.cpp))
- **vLLM** is a higher-throughput serving engine with batching, caching, quantization, and an OpenAI-compatible server, better suited to service operation than casual desktop use. ([vLLM](https://docs.vllm.ai/))

The supplied `gamer-pve` record confirms a Ryzen 5 2600, 16 GB DDR4, an RTX 4060-class GPU, and Proxmox VE 9. **Aiden inference:** this is credible future small-model/quantized-model test capacity, but no exact VRAM figure, actual-task benchmark, quality target, or operational need has been established. It should not be described as frontier-model replacement capacity.

## 6. Potential capability gaps

### Immediate, demonstrated gaps

1. **Real-task evaluation discipline.** There is no compact task set and scorecard separating model quality from application capability, context setup, and owner effort.
2. **Native artifact-to-canonical handoff.** Aiden needs a clear promotion path from a researched/drafted artifact into reviewed canonical repository knowledge without treating chat memory or a generated file as truth.
3. **Agent authority boundaries.** The architecture states that AI increases agency and Atlas remains deterministic, but local edits, command execution, cloud delegation, connector reads, external writes, and purchases need explicit levels.
4. **Usage visibility.** Work and Codex now share a compute/credit pool, but no Aiden log records task type, model, credits/limits, elapsed time, or owner interventions.

### Plausible but unproven gaps

- **Independent critique:** a second provider may catch architectural blind spots or communicate differently, but this must be shown on matched work.
- **Source-bounded learning:** NotebookLM may be better than broad research tools for interrogating a fixed repository-document packet, but the need is not yet recurring.
- **Editor-native assistance:** completion and low-latency in-editor help may be valuable, but Codex has not yet been tested.
- **Programmatic AI:** structured extraction, classification, change review, or mission-status synthesis may later fit Atlas, but the current mission correctly favors deterministic reasoning over premature probabilistic automation.
- **Private/offline inference:** the hardware path exists, but there is no sensitive, offline, high-volume, or latency-critical task that cloud controls fail to satisfy.

## 7. Native application versus API-access distinctions

| If Aiden obtains… | It gains… | It does **not** automatically gain… |
|---|---|---|
| ChatGPT Plus | ChatGPT models plus Projects, memory, Work, Deep Research, Codex, browser, apps, artifact tools, and approvals | OpenAI API credits or a production application backend |
| Claude Pro | Claude app plus Projects, Research, Claude Code, Cowork, and plan usage | Anthropic API credits; unlimited use; necessarily included access to every newest premium model |
| Google AI Pro | Gemini consumer app and Google-native bundle including NotebookLM/Jules benefits | Gemini API billing, Google Cloud IAM, or Agent Platform runtime |
| A Claude model through Poe/OpenRouter/Perplexity | That intermediary's prompt envelope and access to a specified Claude model | Claude Projects, Memory, Research, Claude Code, Cowork, identical limits, or identical system behavior |
| A GPT model through an API/router | Programmatic inference, tool calls, and structured output supported by that endpoint | ChatGPT Project memory, Work, Deep Research, Codex, Library, or consumer-plan allowances |
| A model in Bedrock/Foundry/Agent Platform | Cloud-governed inference integrated with that cloud's identity, network, logging, data, and runtime | The model maker's consumer application or a ready-made personal workflow |
| An open-weight model | Inspectable/downloadable weights under its license and choice of runtime | Adequate actual-task quality, safe tool use, easy operations, or zero total cost |

**Decision rule:** buy a native subscription for a recurring native workflow; use an API for a bounded program; use a router when multi-provider routing is itself required; use a cloud platform when application operations and governance are required. Do not use one as a proxy for another.

| Plus + Poe | **from $24.99/month total** | Adds breadth but loses native provider workflows and adds point/provider complexity | No current case |
| ChatGPT Pro instead of Plus | **$100 or $200/month** | Same ecosystem, much more capacity, Sol Pro | Only for measured cap pressure or Pro-only value |
| ChatGPT Business for one owner | **minimum $50 month-to-month** or $40/month on annual billing for two seats | Adds workspace/admin/no-training defaults, but pays for an unused second seat; API separate | No current case |

Temporary evaluation overlap is acceptable because it buys evidence. Permanent overlap should require a distinct recurring capability. Bundle value—storage, media, office integration, or entertainment—should count only if the owner would otherwise buy and use that benefit.

### Usage-priced access is a different budget

- **APIs have zero necessary monthly subscription but variable spend.** Token, tool, search, storage, runtime, and data-transfer charges can all apply.
- **Agentic subscription overages can behave like APIs.** OpenAI credits extend supported features after included use and expire after 12 months; Claude usage credits bill at standard API rates after plan limits. Auto top-up should remain off during any future pilot unless a deliberate monthly cap is approved. ([OpenAI credits](https://help.openai.com/en/articles/12642688-using-credits-for-flexible-usage-in-chatgpt-freegopluspro-sora), [Claude credits](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans))
- **OpenRouter does not make native subscriptions redundant.** Its economic case is consolidated API access, routing, and fallback—not consumer-app replacement.
- **Major cloud pricing is multi-dimensional.** Model inference can be only part of the bill; agent runtime, search, vector storage, networking, observability, and provisioned capacity can dominate. There is no honest single “Bedrock versus Foundry versus Google” seat price.
- **Local AI is not free.** Count hardware opportunity cost, power, storage, model downloads, patching, observability, backup, security, and owner time.

## 9. Privacy and authority considerations

### Practical data-control comparison

| Surface | Confirmed data-control fact | Practical Aiden stance |
|---|---|---|
| **ChatGPT Plus / Codex** | Individual content may be used for training unless opted out. The owner's training setting is off, so new chats are not used for model training. Codex has separate controls for full-environment training. API and business inputs/outputs are not used for training by default. ([OpenAI data use](https://help.openai.com/en/articles/5722486-how-your-data-is-used-to-improve-model-performance)) | Keep training off; verify Codex full-environment control before a sensitive repo pilot; avoid attaching secrets; feedback can include the associated conversation. |
| **Claude consumer / Claude Code on Pro** | Chats and coding sessions are used to improve Claude only when the user allows it, except safety review or other explicit opt-in. Deleted chats leave back-end systems within 30 days; data allowed for improvement may remain de-identified in training pipelines up to five years. ([training](https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training), [retention](https://privacy.claude.com/en/articles/10023548-how-long-do-you-store-my-data)) | Before any future sensitive pilot, verify “Help Improve Claude” is off or use non-sensitive/synthetic material. Do not infer commercial API protections from a consumer plan. |
| **Gemini consumer** | With Gemini Apps Activity on, data can be used to improve products and a subset may be human reviewed. Turning it off prevents future chats from training models unless feedback is submitted, although service/safety retention still applies. ([Gemini Privacy Hub](https://support.google.com/gemini/answer/13594961?hl=en)) | Use only public or deliberately sanitized Aiden material until settings and connector scopes are verified. |
| **Poe** | Chat content and uploaded files are shared with the providers/developers powering a bot; developers can view/store chats on their servers and may train their models. ([Poe privacy](https://poe.com/pages/privacy)) | Poor default for sensitive repository context. Verify the exact bot/provider policy for every use. |
| **OpenRouter** | It logs metadata but not prompts/completions by default; requests still go to a chosen inference provider. Privacy settings and ZDR routing can reject non-compliant endpoints. ([data collection](https://openrouter.ai/docs/guides/privacy/data-collection), [ZDR](https://openrouter.ai/docs/guides/features/zdr)) | If later used, pin providers, disallow training, require ZDR where needed, and record the full routing policy. |
| **Bedrock / Foundry / Google Cloud** | Bedrock model providers do not have access to Bedrock logs or customer prompts/completions. Models sold by Azure do not expose prompts/outputs to model providers or train foundation models without permission. Cloud platforms add IAM, region, encryption, network, and audit controls. ([Bedrock data protection](https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html), [Foundry privacy](https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/openai/data-privacy)) | Valuable when a production application needs those controls; excessive operational surface for current personal workflows. |
| **Local offline runtime** | A properly configured offline runtime can keep prompts and documents on-device; LM Studio explicitly documents this behavior. | Strongest data-locality option, but only after model files, telemetry, runtime supply chain, backups, host access, and network behavior are verified. |

Training opt-out is not zero retention, zero human access, zero logging, or zero third-party exposure. Connector data can be copied into prompts; browser/computer-use agents can encounter prompt injection; terminal agents can reveal secrets through commands or logs.

### Proposed Aiden authority ladder

| Level | Agent authority | Pilot rule |
|---:|---|---|
| 0 | Public/synthetic information; no connected tools | Safe default for product comparison |
| 1 | Read approved local files or a repository; no writes | Claude Free comparison and initial Codex orientation |
| 2 | Edit an isolated branch/worktree or draft artifact | Allowed in Codex pilot after scope declaration |
| 3 | Run approved tests, linters, builds, and deterministic Atlas commands | Allowed with command visibility and bounded environment |
| 4 | Create/push commits, open PRs, send messages, change cloud state, or use authenticated browser actions | Separate explicit human approval for each external effect |
| 5 | Deploy, delete, alter production, expose secrets, purchase, enable auto-spend, or change account/security settings | Outside these pilots; requires a new decision and authorization |

The agent may propose; Atlas and tests may verify deterministic facts; the owner decides what becomes canonical and what external authority is granted.

## 10. Unknown unknowns and categories for continued awareness

1. **Compute-metered consumer plans.** Google has shifted to five-hour/weekly compute-used limits; OpenAI and Claude expose optional overage credits; premium models can move in and out of included allowances. A “$20 plan” is no longer always a flat capability envelope.
2. **Native agent convergence.** Work, Cowork, Gemini Spark/Antigravity, Perplexity Computer, and browser agents are converging on files, browsers, schedules, and external actions. Authority design will matter more than a static feature checklist.
3. **Model aliasing and product lag.** A model can appear first in one API, later in a consumer app, or under different effort/context rules. Third-party access may lag or silently route differently.
4. **Provider/platform consolidation.** Vertex AI evolved into Gemini Enterprise Agent Platform in April 2026. Product categories and old comparison articles can become obsolete even when the underlying service continues.
5. **Prompt injection through tools and connectors.** Browsing, MCP, email, documents, and code can contain adversarial instructions. Read-only is safer, not risk-free.
6. **Context quality versus context size.** Larger windows do not guarantee correct source selection, durable memory, or repository truth. Atlas-derived context and explicit citations remain more valuable.
7. **Multi-agent orchestration.** Parallel subagents can improve throughput but also multiply spend, inconsistency, and authority. Aiden should require traceable decomposition and a final responsible reviewer.
8. **Open-model quality and licensing.** Smaller/open models are improving quickly, and hosted open-model inference may become a middle path between direct frontier APIs and local deployment. Actual-task evaluation and license review remain necessary.
9. **Agent evaluation/observability standards.** Traces, replay, evaluation datasets, and task-level cost accounting are becoming platform capabilities. Aiden may eventually need a provider-independent record tied to Atlas missions and Git commits.
10. **Specialized modalities and domains.** Voice, image/video, science, security, and computer-use tools may create value later, but none should displace the current Engineering Review milestone without a demonstrated task.
11. **Education/open-source access.** GitHub and some providers offer eligibility-based access. Verify eligibility at the time of need; do not buy a duplicate coding seat first.
12. **Search and retrieval APIs.** A future Aiden research service may need source acquisition and citation verification separately from text generation. That is a different architecture from a research subscription.

## 11. Three recommended bounded pilots, in priority order

Use one shared scorecard for all pilots:

- task success and verified correctness;
- source/citation fidelity where relevant;
- total elapsed time and owner active minutes;
- number and severity of owner interventions;
- post-output editing time;
- context-preparation and artifact-handoff friction;
- understanding gained by the owner;
- authority or privacy mistakes;
- usage/credits consumed and cap interruptions.

Score “understanding and agency” explicitly. Faster output that the owner cannot explain is not a win.

### Pilot 1 — ChatGPT Work + Deep Research on two real Aiden deliverables

**Purpose:** test the highest-value included non-code environment.

**Scope:**

1. One current-information research report with a predeclared primary-source requirement, citations, and Markdown deliverable.
2. One Aiden engineering decision brief derived from a fixed repository-document packet, with an explicit fact/inference split and no repository writes.

This report can be scored as the first artifact if it was produced through Work, but require a second task before drawing a conclusion.

**Bounds:** maximum two hours of owner active time per task; read-only sources; no external writes, messages, publishing, or scheduled actions; no purchased credits.

**Success evidence:** both artifacts are substantially complete, citations survive spot checks, and median owner edit/handoff time is at least 20% lower than the proven Project-chat workflow without reducing understanding.

**Stop condition:** citations are materially unreliable, artifact correction takes as long as manual production, or shared agentic usage becomes a recurring blocker.

### Pilot 2 — Codex on one bounded Atlas Engineering Review task

**Purpose:** determine whether included repository-native execution strengthens the current mission without weakening deterministic practice.

**Scope:** select one already-understood, non-production task supporting Engineering Review. Begin with repository status, canonical instructions, Atlas bootstrap/review, and tests. First run read-only orientation; then permit one isolated branch/worktree change with predeclared files and behavior.

**Required outputs:**

- concise understanding of current mission and relevant architecture;
- proposed plan before edits;
- inspectable diff;
- executed validation/tests and exact results;
- explanation of why the change belongs in the reusable reasoning layer;
- no push or PR without separate human approval.

**Bounds:** one task, one worktree/branch, two-hour active-time budget, no production access, no secrets, no destructive commands, no account changes, no external repository write.

**Success evidence:** a correct, reviewable change with fewer context-transport steps and at least 25% less owner mechanical effort than the current chat-to-terminal artifact workflow, while Atlas/test discipline and owner comprehension remain equal or better.

**Stop condition:** Codex bypasses source-of-truth order, duplicates logic in commands, makes unexplained edits, needs broad authority, or saves no real handoff effort.

### Pilot 3 — Matched Claude comparison, free first and paid only through a gate

**Purpose:** test an independent provider and its native environment, not merely a model name.

**Stage A: Claude Free, read-only.** Run two matched tasks using the same packets and acceptance criteria as ChatGPT: one architecture/source synthesis and one code-review/plan task. Use public or sanitized context and verify model-improvement settings before any sensitive material.

**Gate to Stage B:** authorize one month of Claude Pro only if Claude Free is competitive on quality or materially better on one task, and Free limits or lack of Claude Code/Cowork prevent testing the suspected recurring advantage.

**Stage B: one month of Claude Pro.** Run at least four matched real tasks across Claude Code and/or Cowork. Use included models and plan capacity only; do not enable unlimited usage credits or Fable 5 overage for the pilot.

**Success evidence for a standing subscription:** Claude wins at least four of six matched tasks overall and shows at least one recurring native advantage—such as lower coding intervention in Claude Code or better artifact work in Cowork—with at least 20% lower median owner edit/intervention time. Novelty or stylistic preference alone does not qualify.

**Stop condition:** benefits are model-level but accessible adequately through the incumbent, native tools duplicate Work/Codex, limits disrupt normal tasks, or the owner cannot name a weekly workflow that would move to Claude.

### Reserve pilots after the top three

- NotebookLM Free for a fixed Aiden source packet if source-bounded learning becomes recurring.
- GitHub Copilot Free/Student or Jules Free if an IDE-completion or GitHub cloud-agent gap remains after Codex.
- Perplexity Free versus ChatGPT Deep Research on the same current-information question before any Perplexity subscription.

## 12. Evidence required for future stack decisions

The thresholds below are **proposed Aiden operating gates**, not provider facts.

| Decision | Evidence that would justify it | Evidence that would reject it |
|---|---|---|
| **Keep ChatGPT Plus only** | Work and Codex pass their pilots; no recurring Plus cap; Deep Research is adequate; external tools fail to reduce median owner edit/intervention time by ≥20% across at least six matched tasks; the Project/Library continuity remains valuable. | A second environment repeatedly provides a missing weekly capability or materially better verified outcomes. |
| **Add Claude Pro or another direct subscription** | At least six matched tasks across two recurring workflows; ≥4 wins; ≥20% lower median correction/intervention time or a native capability unavailable in Plus; normal work fits plan limits; owner can name the weekly tasks that move. | Difference is mostly voice/style, latest-model novelty, benchmarks, or duplicated chat access; extra credits are routinely required. |
| **Replace ChatGPT Plus** | Alternative wins at least 70% of ten varied core tasks over 4–6 weeks; Project memory/Library/Work/Codex have no remaining unique recurring value; migration and context-rebuild costs are acceptable; no Plus-only workflow occurs for a full billing cycle. Run at most one evaluation cycle in parallel, then keep one. | Incumbent's continuity or bundled native tools still save meaningful time, or the alternative wins only one specialty. |
| **Use a multi-model consumer service** | Comparing three or more providers is itself a weekly workflow for four weeks; the point pool is cheaper and simpler than direct alternatives at measured usage; required models/versions/contexts are stable; native provider capabilities are unnecessary; privacy terms fit the data. | The need is actually one provider's native Code, Work/Cowork, Projects, Research, or connectors; model access is inconsistent; sensitive context crosses unclear bot/provider policies. |
| **Add direct API access** | A concrete recurring job has a versioned input/output schema, at least 20 representative evaluation cases, deterministic pre/post-processing, known human approval points, secret management, logs, retry behavior, and a monthly budget. A chat workflow is measurably the bottleneck. | Goal is merely “use the model from code,” interactive chat remains sufficient, or no quality/cost baseline exists. Start with one direct provider. |
| **Add an API router** | The direct-API pilot proves a real need for at least two providers, fallback, routing, or consolidated evaluation; provider pinning, retention/training policy, and failure semantics are tested. | One provider meets the workflow; routing adds policy, debugging, and billing complexity without measurable resilience or quality value. |
| **Introduce local AI** | A recurring workload has a demonstrated privacy, offline, latency, marginal-cost, or model-control need; at least 20 actual cases show an available quantized model meets the task's quality threshold; hardware VRAM/RAM, throughput, power, storage, and operations are measured; a fallback and update policy exist. | Motivation is ownership in the abstract, frontier replacement, unused hardware, or assumed free inference; cloud controls already satisfy the task. |

### Resulting decision sequence

1. Extract value from the incumbent native environment.
2. Measure a credible independent native alternative.
3. Add one paid product only for a named recurring capability.
4. Add direct API access only when Atlas/Aiden has a bounded programmable job.
5. Add a router only after multi-provider requirements appear.
6. Add local inference only after a workload and hardware benchmark make the need concrete.

This sequence preserves provider independence without paying for theoretical optionality.
